## 1. 概述与测试体系架构

### 1.1 方案编制背景与交付目标
《极光灵动 · AI-MA 异构协同与自适应灯光操作系统 v5.3.0 Enterprise LTS》采用“Rust 44Hz 硬实时微内核 + Python 业务调度与意图理解层”的双进程混合架构。为了向客户提供具备工业级可信度、高透明度且完全可复现的质量凭证，本方案对 `tests/` 目录下的 **现役全量 31 款自动化测试套件** 进行了系统性治理、架构协同适配与工程规约。

本方案旨在明确：
1. **测试全景与目的**：每一个测试套件针对的底层模块、业务场景、项目合规要求与验收目的；
2. **执行标准与判据**：每一个测试套件的精确运行命令、前置环境依赖、网络/端口约束以及严格的通过（PASS）准出标准；
3. **交付成果物闭环**：指导如何组织“测试源码”、“执行环境”与“测试验收报告”，确保客户方验收人员能够一键复现并签发验收准入令。

## 2. 测试运行前置准备与安全纪律

### 2.1 运行环境基线配置
- **操作系统**：Windows 10/11 Enterprise 或 Debian 12 / Ubuntu 22.04 LTS；
- **Python 运行时**：Python 3.12 运行时（需随附 `numpy >= 2.0.0`、`PyO3` ABI 模块 `aima_shm_sdk.pyd` / `.so`）；
- **微内核二进制**：`bin/aima-rt-daemon.exe`（Windows）或 `bin/aima-rt-daemon`（Linux ELF）；
- **执行解释器命令**：采用 Harness 推荐的标准解释器路径，或虚拟环境中的 `python`。

### 2.2 全局资源独占性纪律（防黑场安全红线）
1. **单例端口与共享内存互斥**：系统真实运行占用 TCP `9000` 端口及 `/dev/shm/aima_slot_*` 内存槽位。
2. **非侵入式测试保护**：凡涉及端口拉起的测试套件（如 `test_aima53_boot_e2e.py`、`test_release_package_integrity.py`），内置检测逻辑：若检测到现有 AI-MA 服务或微内核正在运行，**强制退出并返回退出码 2，严禁执行 taskkill 杀除既有进程**，以防止生产演艺现场发生非预期黑场事故。

### 2.3 数据保护与快照机制
部分历史回归套件（Tier 4）在运行时会读写真实 `knowledge_base/` 与 `config/`。运行回归测试前，必须通过 `tools/documentation/run_verify_suites.py` 自动执行 MD5 目录快照比对，并在测试结束后执行自动回滚清理，保持测试环境“净零污染”。

- **UDP 6454 端口协同架构机理**：
  在 Windows 平台下，由于 UDP 套接字端口复用特性差异，2 类插件（如 `adapter_artnet_dashboard`）若独立绑定 `0.0.0.0:6454` 会与宿主控制台的核心网络抓包器 `ArtNetPacketMonitor` 产生争抢，导致测试注入的真实 ArtDmx 报文偶发拦截。系统实装了**“底层单一网络抓包，宿主 EventHub 解耦广播分发”**的协同架构：
  1. `control_station.py` 的 `ArtNetPacketMonitor` 独占接收真实报文，校验后通过 `engine.event_hub.publish("network.artnet.packet", ...)` 广播至系统总线；
  2. 2 类插件 `plugins/adapters/artnet_dashboard_adapter.py` 在 `on_enable()` 中优先订阅该主题实现免套接字接入；
  3. 彻底根治端口抢占，确保真实节点注入、看门狗报警与自动销警 100% 顺畅。

  4. 真实 ArtDmx 报文注入恢复后自动销警自愈；
  5. 节点手动标记与 RBAC 权限隔离拦截（viewer 角色 403 阻断）。
