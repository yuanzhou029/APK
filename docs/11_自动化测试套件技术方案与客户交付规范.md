## 1. 概述与测试体系架构

### 1.1 方案编制背景与交付目标
《极光灵动 · AI-MA 异构协同与自适应灯光操作系统 v5.3.0 Enterprise LTS》采用“Rust 44Hz 硬实时微内核 + Python 业务调度与意图理解层”的双进程混合架构。为了向客户提供具备工业级可信度、高透明度且完全可复现的质量凭证，本方案对 `tests/` 目录下的 **全部 34 款自动化测试脚本** 进行了系统性梳理与规约。

本方案旨在明确：
1. **测试全景与目的**：每一个测试脚本针对的底层模块、业务场景、项目合规要求与验收目的；
2. **执行标准与判据**：每一个测试脚本的精确运行命令、前置环境依赖、网络/端口约束以及严格的通过（PASS）准出标准；
3. **交付成果物闭环**：指导如何组织“测试源码”、“执行环境”与“测试验收报告”，确保客户方验收人员能够一键复现并签发验收准入令。

## 2. 测试运行前置准备与安全纪律

### 2.1 运行环境基线配置
- **操作系统**：Windows 10/11 Enterprise 或 Debian 12 / Ubuntu 22.04 LTS；
- **Python 运行时**：Python 3.12 运行时（需随附 `numpy >= 2.0.0`、`PyO3` ABI 模块 `aima_shm_sdk.pyd` / `.so`）；
- **微内核二进制**：`bin/aima-rt-daemon.exe`（Windows）或 `bin/aima-rt-daemon`（Linux ELF）；
- **执行解释器命令**：采用 Harness 推荐的标准解释器路径，或虚拟环境中的 `python`。

### 2.2 全局资源独占性纪律（防黑场安全红线）
1. **单例端口与共享内存互斥**：系统真实运行占用 TCP `9000` 端口及 `/dev/shm/aima_slot_*` 内存槽位。
2. **非侵入式测试保护**：凡涉及端口拉起的测试套件（如 `test_aima53_boot_e2e.py`、`test_release_package_integrity.py`），内置检测逻辑：若检测到现有 AI-MA 服务或微内核正在运行，**强制退出并返回退出码 2，严禁执行 taskkill 杀除既有进程**，以防止生产演艺现场发生非预期黑场事故。

### 2.3 数据保护与快照机制
部分历史回归套件（Tier 4）在运行时会读写真实 `knowledge_base/` 与 `config/`。运行回归测试前，必须通过 `tools/documentation/run_verify_suites.py` 自动执行 MD5 目录快照比对，并在测试结束后执行自动回滚清理，保持测试环境“净零污染”。

## 6. 常见故障排查与退出码速查表

| 退出码 / 错误提示 | 触发场景 | 根因与规避处置措施 |
|---|---|---|
| **退出码 `2`** (`[SKIP] 检测到已有 AI-MA 实例在运行`) | 执行 `test_aima53_boot_e2e.py` 或 `run_all_tests.py` | **正常保护逻辑**：检测到 9000 端口或 `aima-rt-daemon.exe` 正在运行。为防止干扰正在使用的系统，测试主动跳过。需先停止既有服务后再运行。 |
| **`PermissionError: [Errno 13]`** | 沙箱写受阻 | 确保在当前项目根目录执行，避免写操作越界访问工作区之外的敏感路径。 |
| **`ModuleNotFoundError: No module named 'numpy'`** | 使用了纯净系统自带 Python | AI-MA 共享内存与遥测依赖 `numpy`，必须指定使用随附的专用运行时 Python 执行测试。 |
| **`ERR-PLUGIN-FOUNDATION`** | 装载 3 类插件时报错 | 该 3 类插件所依赖的 2 类适配器插件未启用或缺失，属于阶梯依赖硬核保护拦截，检查对应 2 类插件是否已装载。 |
